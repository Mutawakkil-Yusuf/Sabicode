The real problem

You can read English. Debugging is still harder in it.

You know the logic. You know what you wanted the code to do. Then Node prints a red paragraph that assumes you already know terms like undefined, reference, module resolution, and stack trace. Now you are translating before you can even start.

01

The message assumes you already know.

Cannot read properties of undefined is not a sentence about your code. It is jargon. You have to decode it before you can fix anything.

02

Search gives you answers, not understanding.

You find a fix for someone else's file. It works today. The next error looks completely new, so you search again.

03

The gap is language, not ability.

You already know how to think. The error is the part that has not met you where you are. That is a tooling problem, not a you problem.

You are not slow. The error is speaking over your head.

How it works

One command. Three things happen.

Sabicode sits between Node and you. It does not hide the real error. It gives you a way into it.

Run your file

Use sabi instead of node. Everything after the script path goes to your script untouched.

npx sabicode app.js

Read the Pidgin

The error line becomes a short Pidgin headline. Then the same three sections every time: what happened, what to do, and what to learn.

🦜 TypeError: You try collect `name` from `undefined`
   Wetin happen: You wan pick `name` from ...
   Wetin to do:  Check am first before you collect:
   Learn am:     `undefined` mean say nothing dey there.

Keep the English

The original error stays in an English: line. The code frame and stack trace stay in place, so you can still search, paste, and talk to your team.

   English: TypeError: Cannot read properties of
            undefined (reading 'name')
    at Object.<anonymous> (/app.js:2:13)

Why this is rare

Not a translation layer. A dictionary with receipts.

Most “explain this error” tools send your code to a model and hope the answer is useful. Sabicode does the opposite: a small, reviewed, versioned dictionary that runs on your machine.

01

A dictionary, not a chatbot.

Every explanation is written, versioned, and reviewed. No AI, no API key, no network. The same error always gets the same answer, so you can trust it while you learn.

02

English stays in the room.

The original error is kept in an English: line, and Learn am: teaches the real term. You get unstuck now and sound like the industry later.

03

Terminal-native.

Exit codes are preserved. stdout stays clean. The code frame and stack trace stay where they are. Zero runtime dependencies, so it starts fast and works offline.

04

Pidgin first, not Pidgin last.

Nigerian Pidgin is the default, not a setting buried in a menu. Street and normal tones. Native speakers review the copy; until then, every entry is marked draft.

05

Real coverage, with tests.

Before / after

The same bug. Two ways to meet it.

Plain Node

/app.js:2
console.log(user.name);
            ^

TypeError: Cannot read properties of undefined (reading 'name')
    at Object.<anonymous> (/app.js:2:13)
    at Module._compile (node:internal/modules/cjs/loader:1521:14)

Correct, but it assumes you already know what undefined means in this exact place.

With Sabicode

🦜 TypeError: You try collect `name` from `undefined`
   Wetin happen: You wan pick `name` from inside empty hand.
                 The thing na `undefined`, e get nothing to give you.
   Wetin to do:  Check am first before you collect:
                 `thing?.name`
   Learn am:     `undefined` mean say nothing dey there.
   English: TypeError: Cannot read properties of undefined
            (reading 'name')

   Polly: Oya, run am again.

The bug is still there. Now you know what it means, what to do next, and the English term for it.

Two commands

When it crashes. Before it crashes.

Runtime errors and potential bugs are different jobs. Sabicode gives each one a command.

sabi run app.js

When the program already broke. Sabicode runs the file with Node, catches the error, and explains it in Pidgin while keeping the English and the stack.

$ sabi run app.js
🦜 ReferenceError: You call `name`, but JavaScript no sabi am
   Wetin happen: You dey call `name` like say JavaScript know am...
   English: ReferenceError: name is not defined

Also works as npx sabicode app.js or npx sabicode run app.js.

sabi scan

Before it breaks. Sabicode runs your project's ESLint, then explains the findings in Pidgin. It finds potential bugs like unused values, loose equality, unreachable code, and undefined names.

components/UserCard.jsx:6:46  error  eqeqeq
🦜 You use `==`, but `===` dey safer
   Wetin happen: `==` dey compare after e change the values...
   English: Expected '===' and instead saw '=='.

Sabicode does not bundle ESLint or call the network. Install ESLint in your project once, and sabi scan uses it.

Open source

The dictionary is the product.

The Pidgin is not magic and it is not generated on the fly. It is JSON entries with samples, tones, and a review hash. That means you can read it, question it, and improve it.

  • Pidgin speakers review headlines, explanations, and tone. A review is tied to the exact content, so edits mark it stale.
  • Developers add adapters, surfaces, and tests. The CLI uses only Node built-ins.
  • Educators report what learners actually hit and help shape the concepts.
